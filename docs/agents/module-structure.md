# Piano lesson structure

Read the reference lesson named in `PROFILE.md` before authoring. Preserve topic IDs from `docs/CURRICULUM.md` and link the lesson from its parent phase README.

## Complete lesson

- `README.md`: purpose, prerequisites, observable objectives, approximate practice allocation, lesson links, exact independent check, allowed conditions, pass criteria, and later review.
- `notes.md`: short original explanations, keyboard/notation examples, practice checks, common mistakes, and source references.
- `exercises.md`: a manageable set of required keyboard, rhythm, reading/listening tasks suited to the lesson. Mark optional variations clearly. Link to the one canonical check in the README.
- `solutions.md`: separate corrections, expected answers where relevant, and feedback rubric. Reference the same check instead of duplicating a drifting version.

Use playable original examples or precise references to an inspected readable source. Do not copy commercial scores into the repo. An exercise must specify hand/register, rhythm, fingering where useful, and tempo/beat unit when relevant. Letter-name patterns do not assess staff reading; familiar pieces do not assess fresh reading.

Prefer one representative complete lesson over many empty module folders. Phase outlines can describe future scope without fabricated exercises, pass criteria, or completed progress. Author later modules as they become current within the user's requested scope.

Keep learner logs in `practice/` and actual piece records in `repertoire/`. Do not prefill attempts or reflections. Creating a lesson never checks its topic in `PROGRESS.md`.
